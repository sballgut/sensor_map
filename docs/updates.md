# 검증된 배포 파일 교체

`ReleaseInstaller`는 E 서버의 `/v1/releases/current`에서 manifest를 받고 map, graph, destinations, model 네 자산을 함께 설치합니다. 파일 내용의 의미 해석은 B/C 모듈이 담당합니다. 이 뼈대에는 가짜 지도·그래프·모델을 정상 배포로 포함하지 않습니다.

- `compatibility`는 현재 1만 지원합니다.
- name은 확장자 없는 논리명 `map`, `graph`, `destinations`, `model`입니다. URL의 실제 파일명에는 확장자가 있어도 됩니다.
- 다운로드는 설정한 서버와 동일한 scheme/host/port만 허용하고 HTTP 리다이렉트는 따르지 않습니다.
- 파일당 20MiB, 전체 80MiB 및 manifest 256KiB 제한을 둡니다.
- 파일을 앱 전용 임시 폴더에 저장하고 길이와 SHA-256을 확인합니다. 네 파일 모두 검증된 뒤 버전 디렉터리로 옮기고 AtomicFile의 current/previous 포인터를 교체합니다.
- 같은 버전 이름에 다른 manifest가 오면 거부합니다. 기존 디렉터리를 덮어쓰지 않습니다.
- 네트워크·길이·해시 오류가 발생하면 기존 current 포인터는 유지합니다.
- 이전 배포는 보존되며 rollback은 이전 버전의 파일을 다시 검증한 다음 포인터를 교체합니다.
- 안내 시작 때 `pinForGuidance()`로 현재 버전을 고정합니다. 고정 중에는 설치·롤백을 거부합니다. 안내 종료 때 `unpin()`하고 업데이트를 다시 시도합니다.
- 다운로드 중 안내가 시작되어도 최종 활성화 직전에 다시 고정 여부를 검사합니다.

설치/롤백은 작업 스레드에서 호출해야 합니다. B/C/D는 `activeDirectory()`의 파일을 읽기 전용으로 사용합니다. 새 경로 생성, 그래프 검사, 모델 실행은 각 담당 모듈의 별도 작업입니다.

SHA-256은 전송/저장 손상을 검출하지만 manifest 자체의 출처를 인증하지 않습니다. 실제 외부 배포는 HTTPS와 서버 접근 통제를 구성해야 합니다. 현재 참조 서버의 HTTP 주소는 로컬 개발용입니다.

단위 테스트는 manifest 완전성, 호환 버전, 경로, 동일 origin, 크기와 해시 형식을 검사합니다. 실제 Android AtomicFile 중단 복구, 다운로드 중단, 안내 중 업데이트 경합과 저장 공간 부족은 실기기 시험이 필요합니다.
