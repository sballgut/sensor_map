# 백그라운드 센서 수집

## 사용 방법

1. 앱에서 서버 주소/APP_TOKEN을 저장하고 배치 전송 버튼으로 필요한 로컬 네트워크 권한을 허용합니다.
2. Bluetooth와 시스템 위치 설정을 켜고 수집 모드를 선택합니다. 안내는 GPS 라벨을 요청하지 않습니다.
3. `BLE 수집 시작`을 누르고 주변 기기·정확한 위치 권한을 허용합니다. Android 13 이상에서는 알림 권한도 요청합니다. 알림 거부만으로 수집 시작을 막지는 않으며, 이 경우 중지는 앱에서 할 수 있습니다.
4. 홈으로 이동하거나 화면을 잠가도 서비스가 수집·로컬 저장·배치 전송을 담당합니다. 앱을 다시 열면 같은 세션을 표시합니다.
5. 앱 또는 지속 알림의 `수집 중지`를 누릅니다. Bluetooth를 끄거나 스캔 실패가 발생한 경우에도 수집을 종료하고 진단을 남깁니다.

수집 모드·기준 지점·보정각·동의는 시작 시 고정하며 수집 중 변경할 수 없습니다. 서버 주소와 토큰을 새로 저장하면 다음 자동 전송부터 반영됩니다. 전송 중지 시 이미 진행 중인 요청은 완료될 수 있으며 미전송 데이터는 삭제하지 않습니다. 수집이 중지된 상태에서는 수동 전송 버튼을 사용합니다.

## 구현

- `CollectionService`: 화면에서 시작하는 `connectedDevice|location` 포그라운드 서비스. 알림에서 앱 열기/중지 제공. 서비스는 외부 앱에 노출하지 않습니다.
- `CollectionEngine`: Application context만 보유합니다. BLE 필터, 방향 센서, GPS 라벨, SQLite 기록, TeamBridge, 안내 버전 고정, 전송 상태를 소유합니다. Activity가 파괴되어도 작업 큐/DB를 닫지 않습니다.
- `MainActivity`: 상태 표시와 사용자 입력. onStop/onDestroy에서 서비스나 하드웨어를 중지하지 않습니다. 화면 회전/재진입은 새 수집 세션을 만들지 않습니다.
- 수집 중 partial wake lock을 유지하고 모든 종료/실패 경로에서 해제합니다. 화면을 강제로 켜두지는 않습니다. 장시간 사용 시 배터리 소모가 증가합니다.
- BLE는 0x181A 서비스 데이터 필터와 LOW_LATENCY를 사용합니다. 장시간 스캔의 수신 저하를 줄이기 위해 4분 후 스캔을 중지하고 1초 후 다시 시작합니다. 세션/누적 관측 수는 유지합니다. 수신이 없다는 이유만으로 반복 재시작하지 않습니다.
- 서버 전송은 수집 중 약 30초마다 시도합니다. 실패/네트워크 단절 시 ACK되지 않은 관측을 SQLite에 보관하고 다음 주기에 재시도합니다.
- 안내 모드에서는 GPS_PROVIDER/NETWORK_PROVIDER를 요청하지 않고 GPS 필드를 저장하지 않습니다. BLE 위치 추정에 필요한 위치 권한/서비스 유형 선언은 GPS 좌표 수집과 별개입니다.
- `START_NOT_STICKY`: 강제 종료/프로세스 종료/재부팅 후 몰래 다시 수집하지 않습니다. 앱에서 다시 시작해야 합니다. 최근 앱 목록에서 제거하는 것만으로는 서비스를 중지하지 않지만 제조사 절전 정책에 따라 종료될 수 있습니다.

포그라운드 서비스도 BLE 무손실 수신이나 정확한 5초 간격, Doze 중 즉시 업로드를 보장하지 않습니다. 센서의 광고 주기, 휴대폰 절전 정책, 네트워크 상황에 따라 달라집니다. 기기 재부팅/강제 중지 후에도 이미 SQLite에 기록된 관측은 남습니다.

## 실기기 확인 절차 (아직 수행하지 않음)

| 시험 | 확인할 결과 |
|---|---|
| 수집 시작 후 홈 이동, 화면 잠금 20분 | 알림 유지, 다시 열었을 때 같은 session_id와 증가한 관측 수. CSV에서 5분 전후 간격 비교 |
| 수집 중 화면 회전/최근 앱 제거 후 다시 열기 | 새 세션/중복 스캐너 없이 기존 수집 상태 표시 |
| 시작 버튼 연속 누름 | 단일 세션만 생성 |
| 4분/8분 경과 | 스캔 갱신 후 같은 세션으로 수신 재개; 1초 중단 구간의 누락 여부 기록 |
| 화면 잠금 중 Wi-Fi 끊기, 다시 연결 | 로컬 관측 증가, 재연결 후 ACK 전송/대기열 감소 |
| 알림 중지 및 앱 중지 | BLE/방향/GPS 요청·스캔 갱신·자동 전송 타이머 종료, 알림 제거 |
| Bluetooth 끄기 / 권한 거부 | 충돌 없이 중지 또는 시작 실패 표시, 다시 허용하고 시작 가능 |
| 안내 모드 | GPS 요청 0, 내보낸 CSV의 GPS 필드 비어 있음 |
| 강제 중지/재부팅 | 자동 수집 없음, 기존 기록 보존, 수동 시작 시 새 세션 |

## 개발 검증

전체 Java 소스를 Android 37 SDK에 대해 javac로 컴파일하고 기존 JUnit 36개를 통과했습니다. 설치된 SDK의 D8/AAPT2/zipalign/apksigner로 시험용 APK(`0.2-ae-background`, versionCode 2)를 생성했고 v2/v3 서명 검증도 통과했습니다. 현재 실행 환경의 Gradle은 프로젝트 폴더를 쓰기 불가로 판단하여 구성 단계에서 중단하므로 Gradle assemble/lint 완료로 보고하지 않습니다. 실기기 서비스/권한/화면 잠금 동작은 위 절차로 별도 확인해야 합니다.

Android 공식 참고: [BLE 백그라운드 통신](https://developer.android.com/develop/connectivity/bluetooth/ble/background), [포그라운드 서비스 유형](https://developer.android.com/develop/background-work/services/fgs/service-types).
