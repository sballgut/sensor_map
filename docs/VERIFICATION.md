## 첫 현장 시험

1. LAB와 OPEN_SOURCE 각각 한 대 이상에서 광고 이름·13/8바이트·온도/CO₂·Unix 시각을 확인합니다. 기존 이름 `Opensrc_team4`는 현재 별칭이 아니므로 장치 이름 또는 명시적 레지스트리 확장이 필요합니다.
2. 화면을 켜고 20분 이상 수집합니다. 5분 전후 센서별 관측 수·수신 간격을 CSV에서 비교합니다. 서버의 설치 좌표나 최신값이 BLE 원시 수신을 대체하지 않음을 확인합니다.
3. 안내 모드에서 GPS 요청 카운터 0, CSV의 모든 gps_* null을 확인합니다. Android 위치 접근 계측도 병행합니다. 수집/평가에서만 위치 요청과 라벨이 생겨야 합니다.
4. E 서버를 끄고 수집한 뒤 앱 종료·재실행 및 서버 복구를 시험합니다. CSV record_id와 서버의 고유 ID 집합을 대조합니다. 저장공간 부족·강제 종료 직전 메모리 대기 쓰기는 별도 시험합니다.
5. 방향 센서 지원/미지원, 화면 회전, 자기장 간섭, 고정 보정각을 확인합니다. 방향은 보행 방향과 동일하지 않습니다.
6. 후보 미동의 세션은 근거 제출이 거부되고 동의 세션은 승인까지 진행되는지 확인합니다. B가 실제 추정값을 연결해야 위치·불확실성이 포함됩니다.
7. B/C의 실제 자산 v1/v2로 설치·롤백을 시험합니다. 다운로드 중 Wi-Fi 끊기, 파일 손상, 용량 부족, 앱 프로세스 종료 때 기존 버전 유지 여부를 실기기에서 확인합니다. 안내 중에는 교체가 차단돼야 합니다.

Android AtomicFile의 실제 프로세스 종료 복구, 앱 SQLite 재시작, 파일 시스템 용량 부족, 실 BLE 장시간 간격, 권한 조합은 자동 완료 판정 대상에 포함하지 않았습니다. 이에 대한 시나리오와 모듈 계약은 INTEGRATION.md에 있습니다.
