# 받은 공유 경로 탭

하단 `공유 경로` → `파일 가져오기`에서 Android 파일 선택기로 JSON을 선택한다. 가져온 경로는 기기 앱 저장소에 보관하며 목록에서 이름·목적지·거리를 확인한다. 선택하면 경로 범위로 맞춘 2D/3D 미리보기에서 초록색으로 표시한다. 삭제는 확인 창을 거친다.

정확한 위치 수신 후 개신캠퍼스 안, 경로 시작점 30m 이내에서 `이 공유 경로로 안내 시작`을 누른다. 받은 경로 순서를 그대로 따르며 자동으로 새 경로를 만들지 않는다. 안내 중 `현재 위치에서 다시 찾기`는 새 직접 탐색 경로(파란색)로 바뀐다.

## 파일 계약 (버전 1)

```json
{
  "schemaVersion": 1,
  "id": "unique-route-id",
  "title": "친구가 보내준 경로",
  "mapVersion": "현재 campus.version과 동일한 값",
  "destinationId": "현재 지도 목적지 ID",
  "nodeIds": ["출발 노드 ID", "중간 노드 ID", "목적지 노드 ID"]
}
```

- 파일 최대 256KB, 경로 지점 2~5000개, 보관 최대 100개. ID/제목 최대 100자.
- 동일 ID는 중복 수신으로 안내하고 덮어쓰지 않는다.
- 지도 버전·노드 존재·끝점과 목적지 일치·인접 간선의 연결/통행/일방향을 검증한다. 실패하면 저장/안내하지 않는다.
- 임의 위경도 선이나 외부 링크를 실행하지 않는다. 서버 자동 수신, Android 다른 앱의 공유 시트 수신, QR/링크 가져오기는 아직 없다.
- 명시적으로 가져온 경로 정의만 보관한다. 사용자의 실제 측위·이동 이력은 저장하지 않는다. 앱 데이터 삭제 시 가져온 경로도 삭제된다.
- [시험용 파일](examples/shared-route.json)은 현재 지도에서 연결된 짧은 경로이며 실제 타인이 공유한 기록이 아니다. 앱에 기본으로 삽입하지 않는다.

## 코드 연결

`SharedRouteStore`: 파일 해석·중복 및 크기 제한·기기 보관/삭제.
`SharedRoute.resolve(campus)`: 지도/간선 검증 후 `RouteOrigin.SHARED` Route 생성.
`SharedRoutesScreen`: 목록·빈 상태·가져오기·상세·삭제.
`CampusViewModel.startShared`: 위치 검증 후 공유 경로 그대로 안내.

향후 서버/QR 수신 계층도 같은 검증을 통과한 경로를 공급해야 한다. 현재 임시 파일 계약은 팀의 최종 서버 프로토콜을 대체하지 않는다.
