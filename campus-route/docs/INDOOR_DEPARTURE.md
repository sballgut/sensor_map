# 건물 안/밖 출발 구분 (2026-11-18)

## 사용 흐름

목적지 선택 → 길찾기 → `건물 밖 · 현재 위치로 출발` 또는 `건물 안 · 현재 건물 선택`.

- 실내 출발은 사용자가 현재 건물을 선택한다. 건물 내부에서 임의로 도로에 붙이거나 출입구를 생성하지 않는다.
- 사용자가 알고 있는 출구로 밖에 나온 뒤 `밖에 나왔어요 · 경로 찾기`를 누른다.
- 위치 권한/수신 상태, 30m 이하 제공 정확도, 건물 선택 이후의 새 측위, 선택한 건물 외곽과 정확도 원의 분리를 확인한 뒤 실외 경로를 계산한다.
- 목적지는 다른 건물의 인근 보행로다. 실내 목적지/층/호실까지의 안내는 아니다.
- 공유 경로도 건물 내부 좌표에서 바로 안내를 시작하지 않는다.

## 지도 판정의 의미

OSM 건물 footprint 안의 좌표는 ‘건물 내부 추정’, 밖이지만 정확도 원이 외곽에 걸치면 ‘경계 부근’, 분리되어 있으면 ‘실외 후보’로 구분한다. GPS만으로 실내 여부나 층을 확정하지 않는다. 실외 출발 선택은 사용자 확인을 포함하며 건물 경계 근처 GPS 오차 가능성을 남긴다.

안내 중에는 정확도 원 전체가 건물 내부에 들어가는 경우 진행/도착 판단을 보류한다. 건물 앞 인근 목적지의 도착까지 무조건 막지 않도록 외부 경계 부근이라는 이유만으로 진행을 중단하지는 않는다.

현재 데이터에는 검증된 출입구가 0개이고 실내 통로 그래프도 없다. 따라서 실내 출구까지 자동 경로 안내, 자동 실내/실외 판별, 출입문 통과의 센서 검증은 제공하지 않는다. 다음 단계에는 조사된 출입구 ID·실내 통로·층·연결 outdoor node 및 A/B의 신뢰도 계약이 필요하다.

## 화면/모형 변경

- 지도 안의 현재 위치/정확도/N 방향 정보 블록과 접기 버튼을 제거했다. 위치 권한·서비스 켜기 버튼과 작은 OSM/ODbL 출처 표기는 유지한다. 중요한 수신 상태는 상단 호스트/내비게이션에서 확인한다.
- 3D 아바타는 OpenGL 구체를 늘린 둥근 머리·몸통·팔다리로 렌더링한다. 짙은 남색이며 불확실 상태는 회색이다.
- 화살표는 별도 앞쪽 위치가 아니라 사용자 발밑과 같은 앵커·회전을 사용하고, 연결선이 앞쪽 화살촉으로 이어진다. 임의 보행 모션/좌표 이동은 추가하지 않았다.
